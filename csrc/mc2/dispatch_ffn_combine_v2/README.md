# dispatch_ffn_combine_v2 standalone

This directory contains a standalone multi-rank runner for the int8
`dispatch_ffn_combine` path.

## Current Scope

- Standalone ACL + HCCL + MPI direct launch.
- Deterministic `cpu-golden` data generated by `scripts/gen_data.py`.
- Tensor-list wrapping for `weight1`, `weight2`, `scale1`, and `scale2`.
- FP16 accuracy report with `max_diff`, `max_ratio`, and allowed error count.
- Warmup and measured timing: kernel uses device `get_sys_cnt()` envelope, e2e uses host timing.
- Optional `--skip-golden` mode for large cases: skip CPU golden generation and final output compare.

Current device tiling key is `1000010`; standalone direct-launch function key is `0`.

## One-command Run

`run.sh` generates `out/`, configures CMake, builds the executable, and launches
`mpirun`.

```bash
bash run.sh \
  --soc ascend910_93 \
  --world-size 2 \
  --m 16 \
  --k 128 \
  --n 128 \
  --topk 2 \
  --experts 2 \
  --max-output-size 32
```

The default iteration counts can be overridden either by command-line options or
environment variables:

```bash
export DISPATCH_FFN_COMBINE_V2_WARMUP_ITERS=1
export DISPATCH_FFN_COMBINE_V2_MEASURE_ITERS=0

bash run.sh \
  --soc ascend910_93 \
  --world-size 2 \
  --m 16 \
  --k 128 \
  --n 128 \
  --topk 2 \
  --experts 2 \
  --max-output-size 32
```

For large cases where only kernel execution and timing are needed, skip CPU
golden generation and final accuracy validation:

```bash
bash run.sh \
  --soc ascend910_93 \
  --world-size 2 \
  --m 4097 \
  --k 128 \
  --n 128 \
  --topk 2 \
  --experts 2 \
  --max-output-size 8194 \
  --skip-golden
```

`--skip-golden` passes `--skip-golden` to `scripts/gen_data.py` and exports
`DISPATCH_FFN_COMBINE_V2_SKIP_ACCURACY=1` before launching the standalone
runner. In this mode `rank{rank}_expected_out.bin` is not generated, and the
runner does not copy, write, or compare the final full output tensor.

For large `max-output-size * K`, `run.sh` raises `HCCL_BUFFSIZE` automatically
when the default 200 MB window is too small for the standalone remote-window
layout.

`run.sh` keeps Ascend/HCCL logs quiet by default. Set
`DISPATCH_FFN_COMBINE_V2_VERBOSE=1` when host-side HCCL context and tiling
diagnostics are needed.

## Manual Build And Run

Use this path when reusing an existing generated `out/` case or when you want to
separate build from execution.

```bash
cmake -S . -B build -DSOC_VERSION=ascend910_93
cmake --build build --target dispatch_ffn_combine_v2 -j16

export DISPATCH_FFN_COMBINE_V2_CASE_DIR=$PWD/out
export DISPATCH_FFN_COMBINE_V2_WARMUP_ITERS=1
export DISPATCH_FFN_COMBINE_V2_MEASURE_ITERS=0

timeout --kill-after=10s 80s \
  mpirun -n 2 "$PWD/build/dispatch_ffn_combine_v2"
```

Useful run overrides:

- `--case-mode cpu-golden`
- `--seed 20260515`
- `--atol 1e-3`
- `--rtol 1e-3`
- `--warmup-iters 3`
- `--measure-iters 5`
- `--skip-golden`

## Generated Artifacts

- `out/case.json`
- `out/rank{rank}_expected_out.bin` when golden generation is enabled
- `out/output_rank{rank}.bin` when accuracy validation is enabled

## Notes

The current local machine reports `Chip Name = 910B1`; the latest 2-rank
standalone validation used cards 2 and 3. If `ASCEND_RT_VISIBLE_DEVICES` is not
set, `run.sh` defaults a 2-rank run to cards 0 and 1.
The default standalone command still builds `ascend910_93`, which maps to the
A3/910C branch in the parent repository. If kernel synchronization hangs, first
compare the `ascend910b1` and `ascend910_93` launch/tiling paths.
